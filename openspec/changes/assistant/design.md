# Design

## Context

现有实现以 `agent.py` 组合 veADK Agent、记忆、知识库和工具，以 `lark_tools.py` 封装飞书文档接口，并通过 `agentkit-agent.py` 暴露 AgentKit 服务。外部集成大多为可选配置，核心约束是缺少可选配置时仍能启动和对话，同时保持现有 AgentKit 请求协议与本地调试方式。

## Goals / Non-Goals

**Goals:**

- 沿用现有模块边界实现各项规格，避免不必要的架构重写。
- 明确可选外部能力的初始化、错误处理和降级路径。
- 用无真实网络请求的自动化测试覆盖核心行为和失败场景。
- 保持本地与云端入口复用同一个 Agent 实例及一致的用户、会话语义。

**Non-Goals:**

- 不引入新的前端、消息平台或持久化后端。
- 不更换 veADK、VikingDB、飞书 SDK 或 AgentKit 技术栈。
- 不改变已部署 AgentKit 的接口路径、请求字段或健康检查响应。
- 不在本次变更中迁移已有记忆或知识库数据。

## Decisions

### 1. 保留单一 Agent 组合入口

继续在 `agent.py` 中创建 `personal_assistant`，由指令描述工具选择规则，并将不可用的可选工具从注册列表中移除。这样本地 CLI 和 AgentKit 无需分别维护工具逻辑。替代方案是为不同入口创建不同 Agent，但会导致行为漂移，因此不采用。

### 2. 可选组件采用条件初始化

长期记忆和知识库仅在对应 collection 配置存在时创建；MCP 路由加载失败时仅禁用该工具。长期记忆回调在未配置时直接返回，后端写入失败必须被记录并转化为可观察的失败状态，不能影响已完成的对话响应。

### 3. 飞书 SDK 调用保持延迟初始化和线程卸载

`lark_tools.py` 继续在首次实际请求时构建客户端，使用 SDK 自动管理访问令牌，并通过 `asyncio.to_thread` 避免同步 SDK 阻塞事件循环。凭证缺失时不创建客户端。测试通过注入假的 SDK 模块验证请求、响应和错误路径，不依赖真实飞书凭证。

### 4. AgentKit 入口保持薄封装

`agentkit-agent.py` 只负责请求字段校验、身份和会话传递、调用 Runner 以及返回响应，不复制 Agent 业务逻辑。缺少必需字段时返回明确错误；有效请求保持现有协议。本地 `agent.py` CLI 继续复用同一个 Agent 和短期记忆配置。

### 5. 配置与部署文件按职责修改

运行配置继续由环境变量和 AgentKit `runtime_envs` 注入。`Dockerfile` 由 AgentKit 自动管理，除非构建流程本身需要调整，否则不手工修改；依赖变更集中放在 `requirements.txt`。部署前先在本地执行 mock 测试和入口验证，再构建云端镜像。

### 6. 测试优先覆盖可确定的边界

在现有飞书工具测试之外，为 Agent 配置降级和 AgentKit 请求处理增加单元测试。外部 VikingDB、模型和飞书服务不做 CI 真实调用；云端部署后仅执行健康检查和受控冒烟验证。

## Risks / Trade-offs

- veADK 组件行为随版本变化 → 保持 `requirements.txt` 版本锁定，并用配置测试验证初始化和降级路径。
- 外部服务超时或权限错误影响回答 → 在工具边界返回可理解错误，自动化测试覆盖失败响应，云端保留冒烟检查。
- 长期记忆异步写入失败不易被用户察觉 → 记录明确错误并暴露保存失败状态，不输出虚假的成功确认。
- 条件注册工具会增加配置组合 → 使用参数化测试覆盖关键组合，避免测试所有无意义排列。
- 云端回滚涉及镜像与运行时配置 → 部署前保留当前镜像和运行时配置，验证失败时恢复上一可用版本。

## Migration Plan

1. 在本地安装锁定依赖并运行全部单元测试。
2. 验证缺少可选环境变量时 Agent 与 AgentKit 入口仍可初始化。
3. 构建并部署新的 AgentKit 镜像，先执行健康检查，再执行受控对话冒烟测试。
4. 若验证失败，停止新运行时并恢复部署前的镜像和运行时配置；无需执行数据回滚。
